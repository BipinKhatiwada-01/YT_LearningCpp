# C++ References

> Notes for learning references in C++. Focus: what references mean, how they differ from pointers, and how they're used with functions and objects.

## 1. What is a reference?

A **reference is an alias—another name for an existing object.**

```cpp
int a = 5;
int& ref = a;

ref = 10;

std::cout << a;   // 10
std::cout << ref; // 10
```

There is one `int` object and two names for it. Assigning through `ref` changes `a`, because both names refer to the same object.

Compare a copy:

```cpp
int a = 10;
int b = a;   // b is a separate object
b = 20;      // a is still 10

int& ref = a; // ref is an alias for a
ref = 30;     // a is now 30
```

## 2. References vs. pointers

A pointer is an object that stores an address. A reference is a language-level alias.

```cpp
int x = 10;

int* ptr = &x; // &x obtains x's address
int& ref = x;  // ref becomes another name for x

*ptr = 20;     // dereference pointer; x becomes 20
ref = 30;      // use alias directly; x becomes 30
```

| Feature | Pointer | Reference |
|---|---|---|
| Represents | An address stored in a pointer object | An alias for an object |
| Must be initialized at declaration | No | Yes |
| Can be changed to refer elsewhere | Yes: `ptr = &other;` | No |
| Can represent “no object” | Yes, with `nullptr` | No ordinary null-reference value |
| Access syntax | Usually `*ptr` to access the pointed-to object | Used directly |
| Lifetime risks | Can dangle | Can dangle |

References are often implemented using address-like machinery, but **the C++ language does not require every reference to be implemented as a pointer**. Think in terms of the language's behavior, not a guessed implementation.

### The `&` symbol has different meanings

```cpp
int& ref = x; // in a type declaration: reference
int* ptr = &x; // in an expression: address-of operator
int bits = a & b; // bitwise AND
```

Context determines what `&` means.

## 3. Two core rules

### A reference must be initialized

```cpp
int& ref; // Error
int x = 10;
int& ref2 = x; // OK
```

An ordinary reference declaration must identify the object it aliases.

### A reference cannot be reseated

```cpp
int a = 10;
int b = 20;

int& ref = a;
ref = b; // assigns b's value to a; ref still aliases a
```

After this code, both `a` and `b` contain `20`, and `ref` still refers to `a`.

A pointer behaves differently:

```cpp
int* ptr = &a;
ptr = &b; // ptr now points to b
```

Remember:

- `ptr = &b;` changes the pointer's stored address.
- `ref = b;` assigns `b`'s value to the object referred to by `ref`.

## 4. Passing arguments to functions

C++ commonly uses three parameter styles.

### Pass by value: modify a copy

```cpp
void increment(int value)
{
    ++value;
}

int x = 5;
increment(x);
// x is still 5
```

`value` is a separate parameter object initialized from `x`.

### Pass by pointer: indirect access to the original

```cpp
void increment(int* value)
{
    if (value != nullptr)
        ++(*value);
}

int x = 5;
increment(&x);
// x is now 6
```

The pointer parameter is itself passed by value, but it contains the address of the caller's `x`. Dereferencing it accesses that original object. Because a pointer can be null, the function may need to handle that possibility.

### Pass by reference: use an alias to the original

```cpp
void increment(int& value)
{
    ++value;
}

int x = 5;
increment(x);
// x is now 6
```

The call looks like an ordinary value argument, but `value` aliases the caller's object. No separate `int` copy is made for the parameter.

Use a reference when the function requires an object and should work directly with it. Use a pointer when “no object” or reseating is part of the intended interface.

## 5. `const T&`: read without copying

A **const reference** lets a function inspect an object without copying it or modifying it through that reference.

```cpp
#include <iostream>
#include <string>

void print(const std::string& text)
{
    std::cout << text << '\n';
}
```

This is especially useful for large objects:

```cpp
#include <vector>

void process(const std::vector<int>& values)
{
    // Read values without copying the vector.
}
```

Passing a vector by value creates a separate vector parameter (normally copying its elements from an lvalue argument). Passing by `const` reference avoids that copy.

These declarations mean the same thing:

```cpp
const int& ref = x;
int const& ref2 = x;
```

The `const` applies to the referenced object **through that access path**:

```cpp
int x = 10;
const int& ref = x;

// ref = 20; // Error: cannot modify x through ref
x = 20;      // OK: x itself is not const
```

A reference does not automatically make its object const. Conversely, a non-const reference cannot bind to a const object:

```cpp
const int x = 10;
const int& readOnly = x; // OK
// int& writable = x;    // Error
```

For small, cheap-to-copy types such as `int`, passing by value is often simpler. Use `const T&` when avoiding copies or expressing read-only access is useful—not automatically for every parameter.

## 6. References and temporary objects

A const lvalue reference can bind to a temporary:

```cpp
const int& ref = 10;
```

In this direct local initialization, the temporary's lifetime is extended to match the lifetime of `ref`.

A function can also accept a temporary through a const-reference parameter:

```cpp
void print(const std::string& text)
{
    std::cout << text;
}

print("Hello");
```

The temporary string used for the call remains alive through the full expression containing the call. **Do not return or store that parameter reference for later use** unless you can guarantee the referred object's lifetime.

Temporary lifetime rules have important details; the safe beginner rule is not to assume that a reference makes an object live longer in every situation.

## 7. Dangling references and lifetime

A reference becomes **dangling** when the object it refers to has been destroyed. Using a dangling reference causes undefined behavior.

```cpp
int& bad()
{
    int x = 10;
    return x; // Wrong: x dies when the function returns
}
```

The same general lifetime problem applies to pointers.

A reference does not keep an ordinary local object alive merely by referring to it. When returning a reference, make sure the referred-to object will outlive every use of the returned reference.

Returning a reference to an existing element can be valid:

```cpp
#include <cstddef>
#include <vector>

int& getElement(std::vector<int>& values, std::size_t index)
{
    return values[index]; // Caller must provide a valid index
}

int main()
{
    std::vector<int> values{10, 20, 30};
    getElement(values, 1) = 100; // values[1] becomes 100
}
```

This is safe only while the vector and the referenced element remain valid. Index validity and operations that invalidate references must be considered.

## 8. References in range-based `for` loops

```cpp
std::vector<int> numbers{1, 2, 3, 4};

for (int n : numbers)
    n *= 2; // modifies copies; vector is unchanged

for (int& n : numbers)
    n *= 2; // modifies the actual elements

for (const int& n : numbers)
    std::cout << n << '\n'; // reads actual elements without modifying them
```

Use `T&` when you want to modify each element, `const T&` for read-only access without copying, and plain `T` when a copy is intended or cheap enough.

## 9. References in class interfaces

A member function can return a reference to an existing member rather than a copy:

```cpp
class Person
{
private:
    std::string name;

public:
    const std::string& GetName() const
    {
        return name;
    }
};
```

The caller avoids copying the string, but the returned reference is tied to the `Person` object's lifetime. It must not be used after the object is destroyed, and the API should account for operations that could invalidate the referenced value.

References can also be used as output parameters, but returning a small result object, a pair, or another suitable return type may make an API clearer. Choose based on the intended interface.

## 10. A note on memory and implementation

Avoid the oversimplification “references use no memory” or “references are always pointers underneath.” The language specifies reference behavior, not a required memory layout. A compiler may treat a reference as another name for an object when possible, or use address-like machinery where needed.

For learning and design, focus first on observable behavior: **a reference aliases an object, cannot be reseated, and does not remove lifetime concerns.**

## 11. Lvalue and rvalue references

The ordinary references covered above are **lvalue references**:

```cpp
int& ref = x;
```

C++ also has **rvalue references**:

```cpp
int&& ref = 10;
```

Rvalue references are important for move semantics and perfect forwarding, but those are separate topics. For now, recognize the `&&` syntax without trying to fold it into the basic reference rules.

## Key takeaways

- A reference is an alias for an existing object—not an independent copy.
- A reference must be initialized and cannot be reseated.
- Assigning to a reference modifies the referred-to object.
- Pass by value works with a separate parameter object; pass by pointer or reference can access the caller's object.
- `const T&` provides read-only access without copying, when that is useful.
- Pointers can represent “no object”; ordinary references do not have a null value.
- References can dangle. They do not generally extend object lifetimes.
- `T&` can modify range-loop elements; `const T&` can read them without copying.
- Reference syntax does not tell you the implementation's memory layout.
