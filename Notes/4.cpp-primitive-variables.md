# C++ Variables & Data Types

These notes expand on The Cherno's **"C++ Variables & Data Types"** video and build directly on the previous notes about how C++ source code is processed, compiled, and turned into executable code.

 The main goal is to understand **what variables and data types actually represent**, how different types are stored and interpreted in memory, how integer and floating-point types behave, and why type sizes can differ between platforms. The notes also introduce `sizeof`, signed and unsigned integers, floating-point precision, and fixed-width integer types so you can build a solid foundation for understanding how C++ manages data at a lower level.

---
## 1. What Is a Variable?

Programming is largely about **working with data**.

A variable gives us a human-readable name for a piece of data stored in memory.

For example:

```cpp
int age = 25;
```

This tells C++:

* `int` — the **type**
* `age` — the **name**
* `25` — the **value**

We can then read or modify that value:

```cpp
int age = 25;

std::cout << age;

age = 26;

std::cout << age;
```

The variable `age` gives us a convenient way to refer to the stored data.

Instead of thinking:

> "There is some value located at this particular memory address..."

we can simply write:

```cpp
age
```

---

# 2. Variables Represent Data in Memory

A variable ultimately represents an object stored somewhere in memory.

For example:

```cpp
int age = 25;
```

Conceptually:

```text
Memory

┌───────────────────┐
│        25         │
└───────────────────┘
         ↑
        age
```

The compiler needs to know things such as:

* How much storage does this object require?
* How should its bits be interpreted?
* What operations are valid?
* How should the value be loaded and stored?

That's where the **type** comes in.

For example:

```cpp
int age = 25;
double price = 19.99;
bool alive = true;
```

These are three different types of data.

# 3. Data Types

C++ provides several fundamental data types.

Some of the most important ones are:

```cpp
char
short
int
long
long long

float
double

bool
```

These types are fundamental building blocks for more complicated C++ programs.

For example:

```cpp
int health = 100;
float speed = 5.5f;
bool alive = true;
char grade = 'A';
```

Each variable has a specific type.

The type tells the compiler how the value should be interpreted and what operations should be performed on it.

---

# 4. The Size of a Data Type

One of the most important properties of a type is its **size**.

The size tells us how much storage an object of that type occupies.

For example, on many modern systems:

```text
char    → 1 byte
int     → 4 bytes
double  → 8 bytes
```

However, **you should not assume that every C++ type has the same size on every platform.**

This is particularly important with:

```cpp
long
```

The size of `long` is one of the classic platform differences you'll encounter when moving between Windows and Linux.

---

# 5. C++ Type Sizes Are Not Always Universal

The C++ language specifies requirements and minimum ranges for fundamental types, but it does not require every platform to use exactly the same size for every type.

For example:

```cpp
sizeof(long)
```

can produce different results depending on the platform.

This matters when following tutorials created on Windows while developing on Linux.

---

# 6. `long` on Windows vs. Linux

This is an especially important platform difference.

On typical **64-bit Windows** implementations using Microsoft's compiler:

```text
long = 4 bytes
```

On typical **64-bit Linux** implementations using GCC or Clang:

```text
long = 8 bytes
```

So:

```text
                 Windows x64       Linux x64

char                1 byte            1 byte
short               2 bytes           2 bytes
int                 4 bytes           4 bytes
long                4 bytes           8 bytes
long long           8 bytes           8 bytes
```

This difference comes from different data models used by the platforms.

Windows 64-bit generally uses the **LLP64** model:

```text
int       = 32 bits
long      = 32 bits
long long = 64 bits
```

Linux 64-bit generally uses the **LP64** model:

```text
int       = 32 bits
long      = 64 bits
long long = 64 bits
```

This is an important caveat when following C++ tutorials.

If The Cherno demonstrates something on Windows and says:

```text
long = 4 bytes
```

that can be correct for his environment.

If you're using GNU/Linux, however:

```cpp
sizeof(long)
```

will typically give:

```text
8
```

---

# 7. Don't Memorize Platform Assumptions

Because C++ is portable, don't write code based on assumptions such as:

```cpp
long x;

```

and then assume:

```text
long == 4 bytes
```

Instead, if the exact size matters, use types designed to communicate that requirement.

For example:

```cpp
#include <cstdint>

std::int32_t  a;
std::int64_t  b;
```

This expresses your intent much more clearly:

```text
int32_t  → exactly 32 bits, when provided by the implementation
int64_t  → exactly 64 bits, when provided by the implementation
```

For ordinary application code, you usually don't need to worry about this yet.

But you **should understand the caveat**.

# 8. Integer Types

Integer types represent whole numbers.

For example:

```cpp
int age = 25;
int score = 100;
int temperature = -10;
```

C++ provides several integer types:

```cpp
char
short
int
long
long long
```

Their sizes are not all universally fixed.

A typical modern 64-bit Linux system might have:

```text
char       1 byte
short      2 bytes
int        4 bytes
long       8 bytes
long long  8 bytes
```

A typical 64-bit Windows system might have:

```text
char       1 byte
short      2 bytes
int        4 bytes
long       4 bytes
long long  8 bytes
```

---

# 9. `char`

`char` occupies exactly **one byte**.

```cpp
char letter = 'A';
```

A `char` is an integer type, but it is commonly used to represent a character.

For example:

```cpp
char letter = 'A';

std::cout << letter;
```

Output:

```text
A
```

Under ASCII-compatible character encodings, `'A'` corresponds to the numeric value `65`.

So you can also write:

```cpp
char letter = 65;
```

and commonly get:

```text
A
```

when printing it as a character.

However, don't think of `char` as simply "the ASCII type."

C++ character representation and character encoding have additional rules, and not every execution environment is required to use ASCII.

The important beginner-level idea is:

> `char` is a one-byte integer type commonly used to represent characters.

---

# 10. Why Does `char` Print as a Character?

Consider:

```cpp
char value = 65;

std::cout << value;
```

This generally prints:

```text
A
```

But:

```cpp
int value = 65;

std::cout << value;
```

prints:

```text
65
```

Why?

Because `std::cout` has different overloads for different types.

Conceptually:

```text
char
 ↓
interpret/display as character

int
 ↓
interpret/display as integer
```

The underlying bits aren't enough to tell us how the value should be displayed.

The **type matters**.

---

# 11. `short`

`short` is a small integer type.

It is commonly:

```text
2 bytes
16 bits
```

For example:

```cpp
short age = 25;
```

A typical signed 16-bit range is approximately:

```text
-32,768 to +32,767
```

However, the C++ standard specifies minimum requirements rather than simply saying:

> "`short` is always exactly 2 bytes."

The exact representation and size are implementation-dependent.

If the exact width matters, fixed-width integer types such as:

```cpp
std::int16_t
```

can be more appropriate.

---

# 12. `int`

`int` is the standard general-purpose integer type.

For example:

```cpp
int age = 25;
int score = 100;
int health = 100;
```

On modern mainstream systems, `int` is typically:

```text
4 bytes
32 bits
```

A typical signed 32-bit range is:

```text
-2,147,483,648
to
+2,147,483,647
```

For ordinary whole-number calculations, `int` is usually the first integer type you should reach for.

---

# 13. `long`

`long` is where platform differences become especially important.

You may see:

```cpp
long value = 100;
```

But the size of `long` depends on the platform.

Typical values:

### 64-bit Windows

```text
long = 4 bytes
```

### 64-bit Linux

```text
long = 8 bytes
```

### Why?

Different platforms use different data models.

Windows commonly uses:

```text
LLP64
```

Linux and other Unix-like 64-bit systems commonly use:

```text
LP64
```

The difference is:

```text
LLP64:

int       4
long      4
long long 8
```

versus:

```text
LP64:

int       4
long      8
long long 8
```

So if you're using Linux and The Cherno demonstrates:

```cpp
long value;
```

don't automatically assume it occupies 4 bytes.

Check:

```cpp
std::cout << sizeof(long);
```

On a typical 64-bit Linux system, you'll get:

```text
8
```

---

# 14. `long long`

`long long` is an integer type capable of representing a larger range than `int`.

It is commonly:

```text
8 bytes
64 bits
```

For example:

```cpp
long long population = 8000000000LL;
```

A typical signed 64-bit range is approximately:

```text
-9.22 quintillion
to
+9.22 quintillion
```

The `LL` suffix indicates that the integer literal is intended to have `long long` type.

---

# 15. Signed Integers

Integer types can be **signed** or **unsigned**.

A signed integer can represent positive and negative values.

For example:

```cpp
int temperature = -10;
```

The ordinary integer types are signed by default.

So:

```cpp
int x;
```

is equivalent, for this purpose, to:

```cpp
signed int x;
```

A typical 32-bit signed integer has:

```text
-2^31
to
2^31 - 1
```

which gives approximately:

```text
-2.147 billion
to
+2.147 billion
```

---

# 16. Unsigned Integers

You can use the `unsigned` keyword to create an unsigned integer.

```cpp
unsigned int score = 100;
```

An unsigned integer represents non-negative values.

A typical 32-bit unsigned integer has a range of:

```text
0
to
4,294,967,295
```

Compare:

```text
signed int:

-2,147,483,648
        ↓
        0
        ↓
+2,147,483,647


unsigned int:

0
↓
4,294,967,295
```

Unsigned integers therefore provide a larger positive range for the same number of bits.

---

# 17. Important Caveat: Unsigned Does Not Mean "No Problems"

Unsigned arithmetic has special rules.

For example:

```cpp
unsigned int x = 0;

x--;
```

An unsigned integer cannot represent `-1`.

Instead, unsigned arithmetic wraps modulo the range of the type.

For a typical 32-bit unsigned integer:

```text
0 - 1
↓
4,294,967,295
```

This behavior is well-defined for unsigned integer arithmetic.

This is different from signed integer overflow, which you should **not** rely on wrapping around.

---

# 18. Signed Integer Overflow

Suppose a typical 32-bit `int` reaches:

```text
2,147,483,647
```

and you try to add one:

```cpp
int x = 2147483647;

x++;
```

The mathematical result would be:

```text
2,147,483,648
```

but that value cannot be represented by a typical 32-bit signed `int`.

Signed integer overflow is **undefined behavior** in C++.

This is an important distinction:

```text
Unsigned overflow
→ defined modulo arithmetic

Signed overflow
→ undefined behavior
```

# 19. Floating-Point Types

Integers are useful for whole numbers.

But many programs need fractional values:

```text
3.14
5.5
0.25
-12.75
```

C++ provides floating-point types for this.

The two you'll use most often are:

```cpp
float
double
```

---

# 20. `float`

A `float` is commonly:

```text
4 bytes
32 bits
```

For example:

```cpp
float speed = 12.5f;
```

Notice the `f`:

```cpp
12.5f
```

The suffix tells C++ that the literal is a `float`.

Without it:

```cpp
12.5
```

the literal has type:

```cpp
double
```

So:

```cpp
float a = 12.5f;
double b = 12.5;
```

is the normal way to distinguish the two.

---

# 21. `double`

A `double` is commonly:

```text
8 bytes
64 bits
```

For example:

```cpp
double pi = 3.141592653589793;
```

Decimal literals without a suffix are `double` by default:

```cpp
double value = 5.5;
```

You can explicitly write:

```cpp
5.5
```

for a `double`, or:

```cpp
5.5f
```

for a `float`.

---

# 22. Floating-Point Precision

A `float` or `double` does **not** store arbitrary decimal numbers perfectly.

Floating-point values use a binary representation.

Some decimal values cannot be represented exactly using a finite number of binary digits.

For example:

```cpp
double a = 0.1;
double b = 0.2;

std::cout << a + b;
```

You may encounter output similar to:

```text
0.30000000000000004
```

This isn't necessarily an error in C++.

It is a consequence of finite-precision floating-point representation.

Therefore:

> **Floating-point numbers are approximations of real numbers, not infinitely precise decimal values.**

This becomes especially important in:

* graphics
* physics
* simulations
* scientific computing
* financial calculations

---

# 23. `bool`

A `bool` represents a logical value.

It has two values:

```cpp
true
false
```

For example:

```cpp
bool playerAlive = true;
bool gameOver = false;
```

You can use it in conditions:

```cpp
if (playerAlive)
{
    std::cout << "Player is alive";
}
```

---

# 24. How Much Memory Does `bool` Use?

A standalone `bool` typically occupies:

```text
1 byte
```

not:

```text
1 bit
```

This might seem wasteful because we only need one bit to represent:

```text
0
1
```

However, ordinary objects are stored in addressable memory units, and a standalone `bool` is typically represented using one byte.

Specialized techniques can pack multiple boolean values into individual bits.

But for a normal variable:

```cpp
bool alive = true;
```

you should generally think:

```text
bool
↓
1 byte
```

The C++ standard also guarantees that `sizeof(bool)` is `1`, where the unit is a C++ byte.

---

# 25. `sizeof`

C++ provides the `sizeof` operator to determine the size of a type or object.

For example:

```cpp
sizeof(int)
```

On a typical system this produces:

```text
4
```

because `int` commonly occupies 4 bytes.

You can check several types:

```cpp
std::cout << sizeof(char) << '\n';
std::cout << sizeof(short) << '\n';
std::cout << sizeof(int) << '\n';
std::cout << sizeof(long) << '\n';
std::cout << sizeof(long long) << '\n';
std::cout << sizeof(float) << '\n';
std::cout << sizeof(double) << '\n';
std::cout << sizeof(bool) << '\n';
```

On a typical 64-bit Linux system, you might see:

```text
1
2
4
8
8
4
8
1
```

On a typical 64-bit Windows implementation:

```text
1
2
4
4
8
4
8
1
```

Notice the important difference:

```text
Linux:
long = 8 bytes

Windows:
long = 4 bytes
```

---

# 26. `sizeof` a Variable

You can also use `sizeof` on an actual variable.

```cpp
int age = 25;

std::cout << sizeof(age);
```

This tells you how many bytes the object occupies.

You can also compare:

```cpp
int age = 25;

std::cout << sizeof(int) << '\n';
std::cout << sizeof(age) << '\n';
```

Both will normally produce:

```text
4
4
```

assuming `int` is 4 bytes on the platform.

---

# 27. `sizeof` Is Measured in Bytes

One important detail:

```cpp
sizeof(int)
```

returns a number of **bytes**, not necessarily bytes of exactly 8 bits.

On virtually all modern systems you'll encounter:

```text
1 byte = 8 bits
```

but the C++ standard defines a byte in terms of the size of `char`, not by requiring it to always contain exactly 8 bits.

C++ provides:

```cpp
CHAR_BIT
```

in `<climits>` to determine how many bits are in a byte on the current implementation.

For normal modern desktop development, you can generally think:

```text
1 byte = 8 bits
```

but it's useful to know that this is technically a platform property.

---

# 28. Typical Data-Type Sizes

Here's a useful **rule-of-thumb table**, not a universal guarantee:

| Type        | Typical Linux x64 | Typical Windows x64 | Notes                               |
| ----------- | ----------------: | ------------------: | ----------------------------------- |
| `char`      |            1 byte |              1 byte | Exactly 1 byte                      |
| `short`     |           2 bytes |             2 bytes | Commonly 16-bit                     |
| `int`       |           4 bytes |             4 bytes | Commonly 32-bit                     |
| `long`      |       **8 bytes** |         **4 bytes** | Major platform difference           |
| `long long` |           8 bytes |             8 bytes | Commonly 64-bit                     |
| `float`     |           4 bytes |             4 bytes | Typically IEEE 754 single precision |
| `double`    |           8 bytes |             8 bytes | Typically IEEE 754 double precision |
| `bool`      |            1 byte |              1 byte | `sizeof(bool)` is 1                 |

The important word here is **typical**.

C++ does not simply define:

> "Every computer must have these exact sizes."

It defines requirements that implementations must satisfy.

---

# 29. Why `long` Is a Great Example of Portability

Suppose you write:

```cpp
long value = 100;
```

On Windows x64:

```text
long
↓
4 bytes
```

On Linux x64:

```text
long
↓
8 bytes
```

The source code is identical:

```cpp
long value = 100;
```

but the object representation can differ.

This is one reason you shouldn't assume that C++ source code behaves identically at the binary/layout level across every platform.

If your program needs a specific width, use a fixed-width integer type:

```cpp
#include <cstdint>

std::int32_t value32;
std::int64_t value64;
```

That makes the intent much clearer.

# 30. Fixed-Width Integer Types

C++ provides fixed-width integer types through:

```cpp
#include <cstdint>
```

For example:

```cpp
std::int8_t
std::int16_t
std::int32_t
std::int64_t
```

and unsigned versions:

```cpp
std::uint8_t
std::uint16_t
std::uint32_t
std::uint64_t
```

For example:

```cpp
std::int32_t score = 100;
std::int64_t population = 8000000000LL;
```

The key idea is:

```text
int
↓
at least a certain range, commonly 32 bits

std::int32_t
↓
exactly 32 bits, if the implementation provides the type
```

This is particularly useful for:

* binary file formats
* networking
* serialization
* hardware interfaces
* protocols
* cross-platform data structures

---

# 31. Types Are More Than Their Size

It's easy to reduce the topic to:

```text
int    = 4 bytes
float  = 4 bytes
double = 8 bytes
```

But two types having the same size doesn't make them equivalent.

For example:

```cpp
int a = 5;
float b = 5.0f;
```

Both might occupy 4 bytes.

But they have completely different meanings and representations.

`int` represents an integer.

`float` represents a floating-point value.

They behave differently in:

* arithmetic
* comparisons
* conversions
* precision
* memory representation
* compiler optimizations

So:

> **Size is important, but size alone does not define a C++ type.**

# 32. Variables in a Game

This is where variables become especially useful.

Imagine a game character:

```cpp
float x = 10.0f;
float y = 5.0f;
float z = 2.0f;

int health = 100;

bool alive = true;
```

We now have:

```text
Position:
x = 10.0
y = 5.0
z = 2.0

Health:
100

Alive:
true
```

The program can update these values:

```cpp
x += 1.0f;
health -= 10;
```

Now:

```text
x      = 11.0
health = 90
```

This is the fundamental idea behind variables:

> **They allow a program to keep track of changing state.**

---

# 33. A Complete Example

```cpp
#include <iostream>

int main()
{
    char grade = 'A';

    int health = 100;

    long score = 500;

    long long population = 8000000000LL;

    float speed = 5.5f;

    double distance = 123.456;

    bool alive = true;

    std::cout << "Grade: " << grade << '\n';
    std::cout << "Health: " << health << '\n';
    std::cout << "Score: " << score << '\n';
    std::cout << "Population: " << population << '\n';
    std::cout << "Speed: " << speed << '\n';
    std::cout << "Distance: " << distance << '\n';
    std::cout << "Alive: " << alive << '\n';

    std::cout << '\n';

    std::cout << "sizeof(char): " << sizeof(char) << '\n';
    std::cout << "sizeof(short): " << sizeof(short) << '\n';
    std::cout << "sizeof(int): " << sizeof(int) << '\n';
    std::cout << "sizeof(long): " << sizeof(long) << '\n';
    std::cout << "sizeof(long long): " << sizeof(long long) << '\n';
    std::cout << "sizeof(float): " << sizeof(float) << '\n';
    std::cout << "sizeof(double): " << sizeof(double) << '\n';
    std::cout << "sizeof(bool): " << sizeof(bool) << '\n';

    return 0;
}
```

If you're running this on typical 64-bit Linux, you'll likely see:

```text
sizeof(char): 1
sizeof(short): 2
sizeof(int): 4
sizeof(long): 8
sizeof(long long): 8
sizeof(float): 4
sizeof(double): 8
sizeof(bool): 1
```

On typical 64-bit Windows:

```text
sizeof(char): 1
sizeof(short): 2
sizeof(int): 4
sizeof(long): 4
sizeof(long long): 8
sizeof(float): 4
sizeof(double): 8
sizeof(bool): 1
```

The difference in `long` is the important one to remember.

# 34. A Practical Beginner Mental Model

For now, a useful mental model is:

```text
                    VARIABLE
                       │
             ┌─────────┴─────────┐
             │                   │
            NAME                TYPE
             │                   │
           health                int
                                 │
                                 ▼
                              MEMORY
                                 │
                                 ▼
                                100
```

The **name** lets your source code refer to the object.

The **type** tells C++ what kind of object it is.

The **value** is the data currently stored in it.

The **memory** is where that object is represented while the program runs.
