# C++ Header Files — The Cherno

These notes expand the key ideas from The Cherno’s **“C++ Header Files”** video into a more complete study/reference format.

## 1. What Is a Header File?

A **header file** is typically a `.h` or `.hpp` file used to store code that we want to make available to other `.cpp` files.

The most common thing placed in a header is a **declaration**.

For example:

```cpp
// Log.h

void InitLog();
void Log(const char* message);
```

The header tells other parts of the program:

* `InitLog()` exists.
* `Log()` exists.
* What parameters they take.
* What they return.

The actual implementation can be somewhere else:

```cpp
// Log.cpp

void InitLog()
{
    // implementation
}

void Log(const char* message)
{
    // implementation
}
```

So, at a basic level:

```text
Header (.h)
    ↓
"What exists?"

Source (.cpp)
    ↓
"How does it work?"
```

---

# 2. Why Do We Need Header Files?

C++ allows a program to be split into multiple `.cpp` files.

Suppose we have:

```text
Log.cpp
Main.cpp
```

`Log.cpp` contains:

```cpp
void Log(const char* message)
{
    // ...
}
```

and `Main.cpp` wants to use it:

```cpp
int main()
{
    Log("Hello");
}
```

The problem is that `Main.cpp` needs to know about `Log()`.

We could manually write:

```cpp
void Log(const char* message);
```

at the top of `Main.cpp`.

But imagine having hundreds of functions and classes used across dozens of files.

Manually copying declarations everywhere would be:

* repetitive
* difficult to maintain
* easy to get wrong

Instead, we create:

```cpp
// Log.h

void Log(const char* message);
```

and then:

```cpp
// Main.cpp

#include "Log.h"
```

Now `Main.cpp` gets the declaration from one central location.

### Main purpose

**Header files provide a convenient place to put declarations that need to be shared between multiple source files.**

---

# 3. Declaration vs. Definition

This distinction is particularly important when discussing headers.

### Declaration

```cpp
void Log(const char* message);
```

This tells C++:

> A function named `Log` exists with this signature.

Notice the semicolon.

### Definition

```cpp
void Log(const char* message)
{
    // actual implementation
}
```

This provides the implementation.

A simple way to remember it:

```text
Declaration → tells us WHAT exists
Definition  → provides the actual implementation
```

Header files are traditionally used primarily for the **declaration/interface**.

---

# 4. Header Files as an Interface

A header can act as the interface to a particular part of your program.

For example:

```cpp
// Log.h

void InitLog();
void Log(const char* message);
void ShutdownLog();
```

Someone using the logging system doesn't necessarily need to know how these functions are implemented.

They only need to know:

```text
InitLog()
Log(...)
ShutdownLog()
```

The implementation remains inside:

```cpp
// Log.cpp
```

This creates a useful separation between:

**What is available**

and

**How it is implemented.**

---

# 5. The `#include` Preprocessor Directive

To use a header, we generally write:

```cpp
#include "Log.h"
```

`#include` is a **preprocessor directive**.

It is not a C++ function.

It is handled before the compiler processes the resulting source code.

The most useful mental model is:

> `#include` essentially copies the contents of the specified file into the location of the `#include`.

For example:

### Log.h

```cpp
void Log(const char* message);
```

### Main.cpp

```cpp
#include "Log.h"

int main()
{
    Log("Hello");
}
```

Conceptually, the preprocessor turns this into:

```cpp
void Log(const char* message);

int main()
{
    Log("Hello");
}
```

So the compiler can see the declaration.

---

# 6. `#include` Is Not a Link

This is an important point.

When you write:

```cpp
#include "Log.h"
```

C++ isn't creating some special runtime connection to `Log.h`.

It is essentially saying:

```text
Take the contents of Log.h
and insert them here.
```

This explains why headers can accidentally cause problems if they contain things that should not be defined multiple times.

---

# 7. The Multiple-Inclusion Problem

Because `#include` essentially copies the contents of a file, including a header multiple times can result in its contents appearing multiple times.

Consider:

```cpp
// Player.h

struct Player
{
    int x;
    int y;
};
```

Now:

```cpp
#include "Player.h"
#include "Player.h"
```

Conceptually becomes:

```cpp
struct Player
{
    int x;
    int y;
};

struct Player
{
    int x;
    int y;
};
```

Now `Player` has been defined twice.

This can cause a **redefinition error**.

---

# 8. Multiple Inclusion Can Happen Indirectly

The problem isn't limited to explicitly including the same file twice.

Suppose:

```cpp
// A.h

#include "Player.h"
```

and:

```cpp
// B.h

#include "Player.h"
```

Then:

```cpp
// Main.cpp

#include "A.h"
#include "B.h"
```

Although `Main.cpp` never directly wrote:

```cpp
#include "Player.h"
#include "Player.h"
```

the inclusion chain effectively causes `Player.h` to appear twice.

This is one of the main reasons header files need **include guards**.

---

# 9. `#pragma once`

The simplest modern solution is:

```cpp
#pragma once
```

at the top of the header.

Example:

```cpp
// Player.h

#pragma once

struct Player
{
    int x;
    int y;
};
```

This tells the compiler/preprocessor to process this header **only once per translation unit**.

So if multiple files or headers end up including `Player.h`, the header's contents won't be repeatedly processed within that translation unit.

### Why use it?

It is:

* simple
* concise
* easy to understand
* widely supported by modern C++ compilers

For modern C++ development, `#pragma once` is extremely common.

---

# 10. Traditional Include Guards

Another way to prevent multiple inclusion is the traditional **include guard**.

Example:

```cpp
#ifndef PLAYER_H
#define PLAYER_H

struct Player
{
    int x;
    int y;
};

#endif
```

There are three important preprocessor directives here.

### `#ifndef`

```cpp
#ifndef PLAYER_H
```

Means:

> "If `PLAYER_H` has not been defined..."

### `#define`

```cpp
#define PLAYER_H
```

Defines the `PLAYER_H` preprocessor symbol.

### `#endif`

```cpp
#endif
```

Ends the conditional section.

---

# 11. How an Include Guard Works

The first time the header is included:

```text
Is PLAYER_H defined?
        ↓
       No
        ↓
#define PLAYER_H
        ↓
Process the header
```

The next time:

```text
Is PLAYER_H defined?
        ↓
       Yes
        ↓
Skip the header contents
```

Therefore, the contents are effectively processed only once.

---

# 12. `#pragma once` vs. Include Guards

### `#pragma once`

```cpp
#pragma once

// declarations
```

### Traditional guard

```cpp
#ifndef LOG_H
#define LOG_H

// declarations

#endif
```

Both solve the same fundamental problem:

> **Preventing the contents of a header from being processed multiple times in the same translation unit.**

`#pragma once` is generally much shorter and easier to write.

Traditional include guards are the older/common preprocessor-based technique.

---

# 13. Header Guard Naming

With traditional include guards, the name should normally be unique enough to avoid collisions.

For example:

```cpp
#ifndef MYPROJECT_LOG_H
#define MYPROJECT_LOG_H

// ...

#endif
```

The important part is that the same macro is used in both:

```cpp
#ifndef
```

and:

```cpp
#define
```

For example:

```cpp
#ifndef LOG_H
#define LOG_H
```

not:

```cpp
#ifndef LOG_H
#define PLAYER_H
```

because that would not correctly guard the file.

---

# 14. `#include "..."` vs. `#include <...>`

C++ provides two common forms of `#include`.

### Quotes

```cpp
#include "Log.h"
```

### Angle brackets

```cpp
#include <iostream>
```

They have different intended search behavior.

---

# 15. Double Quotes — `"filename"`

Example:

```cpp
#include "Log.h"
```

This form is generally used for **your own/project headers**.

Examples:

```cpp
#include "Player.h"
#include "Renderer.h"
#include "Log.h"
```

The compiler generally searches relative to the current file's location first, before considering configured include directories.

So if you have:

```text
Project/
├── Main.cpp
└── Log.h
```

then:

```cpp
#include "Log.h"
```

is the natural choice.

---

# 16. Angle Brackets — `<filename>`

Example:

```cpp
#include <iostream>
```

This form is generally used for:

* C++ standard-library headers
* SDK headers
* external library headers
* headers located in configured include directories

For example:

```cpp
#include <iostream>
#include <vector>
#include <string>
```

The compiler searches its configured include directories according to its include-search rules.

---

# 17. Practical Rule

A good rule to remember is:

```cpp
#include "MyHeader.h"
```

→ **My/project header**

and:

```cpp
#include <iostream>
```

→ **standard/external header**

This isn't simply about whether the file physically exists on your computer. It's also about how the compiler searches for the header and the convention being used.

---

# 18. C Standard Library Headers

C++ has inherited much of the C standard library.

Traditional C headers commonly use `.h`:

```cpp
#include <stdlib.h>
#include <stdio.h>
#include <string.h>
```

The `.h` extension is part of the traditional C naming convention.

---

# 19. C++ Standard Library Headers

C++ standard-library headers generally **do not use `.h`**.

Examples:

```cpp
#include <iostream>
#include <vector>
#include <string>
```

Notice:

```text
iostream
vector
string
```

rather than:

```text
iostream.h
vector.h
string.h
```

This is a deliberate convention of the C++ standard library.

---

# 20. Why Do C++ Headers Have No `.h`?

The C++ standard library uses header names such as:

```cpp
<vector>
<string>
<iostream>
```

without requiring a file extension.

This distinguishes the C++-style standard library headers from traditional C headers.

For example:

```cpp
#include <stdio.h>
```

is a traditional C-style header.

Whereas:

```cpp
#include <iostream>
```

is a C++ standard-library header.

The absence of `.h` does **not** mean it isn't a header.

It's simply the naming convention specified by the C++ standard library.

---

# 21. Headers Can Contain More Than Function Declarations

The basic explanation is:

> Header files contain declarations.

That's a useful starting point, but it isn't a strict rule that headers can contain *only* declarations.

For example, a header can contain a class definition:

```cpp
#pragma once

class Player
{
public:
    void Move();

private:
    int x;
    int y;
};
```

The class definition needs to be visible to code that wants to use the class.

Headers can also contain things such as:

* class definitions
* `struct` definitions
* function declarations
* enum declarations
* type aliases
* templates
* inline functions
* constants
* macros

The important idea is that headers contain things that need to be **shared with code that includes them**.

---

# 22. A Typical Header/Source Pair

A simple example:

### `Log.h`

```cpp
#pragma once

void InitLog();
void Log(const char* message);
```

### `Log.cpp`

```cpp
#include "Log.h"

void InitLog()
{
    // implementation
}

void Log(const char* message)
{
    // implementation
}
```

### `Main.cpp`

```cpp
#include "Log.h"

int main()
{
    InitLog();
    Log("Hello");
}
```

The important part for understanding headers is:

```text
Log.h
   ↓
contains the declarations
   ↓
included wherever those declarations are needed
```

---

# 23. Why Not Just Put Everything in `.cpp` Files?

You might wonder:

> If I can write the declaration directly inside `Main.cpp`, why bother creating `Log.h`?

For a tiny program, you could.

But as the project grows, you'll have many things that need to be shared.

For example:

```cpp
void InitLog();
void ShutdownLog();
void Log(const char*);
void SetLogLevel(int);
```

Instead of repeating these declarations in many `.cpp` files, you have one source of truth:

```cpp
Log.h
```

and simply:

```cpp
#include "Log.h"
```

This is the main organizational benefit of header files.

---

# 24. The Core Idea of the Cherno's Explanation

The most important conceptual chain to remember from the video is:

```text
Multiple .cpp files
       ↓
Need to share declarations
       ↓
Put declarations in a header
       ↓
#include the header
       ↓
Header contents are inserted
       ↓
Declarations become available
```

But because inclusion is essentially textual:

```text
#include
   ↓
copy/paste
```

we have to protect headers from being included multiple times:

```text
#pragma once
       OR
#ifndef / #define / #endif
```

And for choosing headers:

```text
"filename"
   ↓
typically local/project header

<filename>
   ↓
typically standard/external header
```

# 26. Final Mental Model

If you want to remember the video in the simplest possible way:

> **A header file is a place where we put information that other source files need to know about.**

For example:

```cpp
// Log.h

#pragma once

void Log(const char* message);
```

Then:

```cpp
#include "Log.h"
```

makes that declaration available to the file.

`#include` essentially performs:

```text
"Put the contents of this header here."
```

Because the same header may get included more than once, we protect it with:

```cpp
#pragma once
```

or:

```cpp
#ifndef
#define
#endif
```

And when including headers:

```cpp
#include "MyHeader.h"
```

is conventionally for your own/local headers, while:

```cpp
#include <iostream>
```

is conventionally for standard-library or externally configured headers.

**That's the core of The Cherno's header-files lesson, without repeating the compiler/linker material you already have notes for.**
